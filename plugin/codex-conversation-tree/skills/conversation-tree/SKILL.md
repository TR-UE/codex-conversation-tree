# 本地对话树

使用本插件的 open_tree_panel 工具打开面板。首次关联时，使用当前对话的真实 threadId；本机可以从 CODEX_THREAD_ID 读取，或从 Codex 的当前会话信息确认。不要猜测 ID，不要订阅未获用户授权的其他对话。

如果当前会话没有加载新的 MCP 工具，也能使用插件内的本机入口：根据本 SKILL.md 所在目录向上两级找到插件根目录，运行 `/bin/sh <插件根目录>/scripts/launch-node.sh <插件根目录>/server/cli.mjs open --thread-id <当前真实对话ID>`。读取返回的 panelUrl，再调用 Codex 的 open_in_codex，以 browser 类型打开这个 URL。用户仍在 Codex 原生会话中提问，面板负责记录与管理。不能只返回 localhost 链接就声称已经打开面板，也不能因此创建独立客户端或猜一个会话 ID。

若用户只想查看已记录的树，没有要求记录当前会话，CLI 的 open 可以省略 --thread-id；此时只打开已有数据。安装一次即可在其他本机对话中按需调用，已有记录持续保留。原生 MCP Apps 视图只有在宿主实际显示后才算验证完成，内置浏览器面板应明确标注。

记录仅保存在桌面的 Codex-Conversation-Tree/data/native。后台只读已关联对话的持久化记录，保存用户文本和可见回答，不保存系统提示、隐藏推理或工具参数。

历史分叉先从 tree_state 找到用户指定的节点，再调用 fork_native_node。它复制历史到节点所属的真实 Codex turnId，保留父对话。返回新的 threadId 后，使用 Codex 原生 navigate_to_codex_page 打开这个分支。没有得到用户继续提问的指令时，不向新分支发送消息。

创建接口会在返回前释放插件自己的写入连接，返回的就是可以交给 Codex 继续使用的那一个原生分支。打开时直接使用返回的 threadId，不再调用 fork_thread 或“创建聊天分叉”生成第二份。若错误明确包含“已经创建”和 threadId，保留并打开这条已有分支，不自动重试创建。

导入旧节点时没有当时的文件快照。明确区分对话分叉和文件恢复，不能把当前文件说成历史文件状态。一个原生轮次中的多次追加输入，只能在该轮次完成后的最后一个节点处分叉。

用户决定哪些结论纳入树根；保存时保留版本与来源节点。面板中点击打开已创建分支，是导航到该已有分支的指令。

用户要求将指定分支设为主分支时，先从 tree_state 确认对象，再调用 manage_branch 的 promote 操作。当前主分支由 native.mainThreadId 表示，旧数据默认采用 native.rootThreadId。主分支切换保留原生历史来源与父子关联、共有节点和树根记忆；不创建额外会话。尚未提问的新分支也可以设为主分支。已剪或已永久删除的会话不能直接设置。不能根据用户询问按钮位置就替用户选择主分支。

用户要剪枝时，先从 tree_state 确认用户指定的原生路径，再调用 manage_branch 的 prune 操作。剪枝会隐藏该路径及子分支并停止同步，可在“已剪分支”中用 restore 操作恢复。当前主分支不能剪掉；切换主分支后可以剪掉旧主线，包括原始主线，剪枝范围会保留新主分支和它的子分支。共有前缀、树根记忆和 Codex 原始聊天继续保留。不能根据用户询问剪枝功能就替用户选一条路径。原始会话仍是原生历史来源，本版不支持永久删除它；包含当前主分支的原生子树也不能整支永久删除。

永久删除原生会话是单独选项，默认关闭。面板先通过 preview_native_deletion 展示真实会话名称、ID 和所有子会话范围，再要求用户输入“删除原生会话”。delete_native_branch 仅对 App 视图开放，模型不能绕过面板替用户输入确认或调用后台删除。已经剪掉的分支可以在“已剪分支”中单独删除原生会话；删除后没有原生恢复入口，桌面的已记录内容和树根记忆仍保留。删除失败或范围变化时如实显示结果，不声称已全部删除。
